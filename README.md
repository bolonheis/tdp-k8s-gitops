# TDP GitOps

ArgoCD manifests repository for deploying Tecnisys Data Platform (TDP) components to Kubernetes, using the **App of Apps** pattern.

## Overview

This repository drives the deployment of TDP (Tecnisys Data Platform) components — PostgreSQL, Trino, Kafka, Airflow, Spark, Superset, and others — onto Kubernetes clusters using ArgoCD's App-of-Apps pattern. Application manifests are kept as envsubst templates under available/, rendered per-environment into current/ (the source of truth ArgoCD watches), and reference versioned Helm charts hosted on Tecnisys' OCI registry. A single deploy.sh script handles ArgoCD bootstrap, template rendering, and both GitOps (git-driven) and direct (kubectl apply) deployment modes.

## Getting Started

This repository (**Tecnisys-OSS/tdp-k8s-gitops**) is the distribution source — kept in sync with each TDP release. **Clone or fork it as the starting point for your own GitOps repository**:

```bash
git clone https://github.com/Tecnisys-OSS/tdp-k8s-gitops.git my-tdp-gitops
cd my-tdp-gitops
```

Then set `GIT_REPO_URL` (in your `variables.env.local`, see [Configuration](#configuration)) to **your own repository** — a fork, or wherever you push this clone to — not to `Tecnisys-OSS/tdp-k8s-gitops` itself. ArgoCD needs to watch a repo you control, where your own rendered `current/` gets pushed; the Tecnisys-OSS source stays read-only and gets overwritten on every release sync.

### How App of Apps works

```
kubectl apply          ArgoCD watches
     ↓                      ↓
common/           →   current/common/   →  AppProject + Secrets + App-of-Apps
                                                       ↓
                        current/          ←  App-of-Apps reads current/ from git
                    (tdp-postgresql/, …)         ↓
                                          Creates Applications in the cluster
                                                  ↓
                                     Helm chart pulled from OCI registry
```

- `available/` contains the **templates** (with `${VAR}`) — **never** applied directly.
- `deploy.sh -p` renders `available/` + `common/` → `current/`, substituting variables.
- `current/` is **committed to git** and watched by the ArgoCD App of Apps.

## Configuration

### 1. Variables

Copy the reference file and edit it with your values:

```bash
cp variables.env variables.env.local
```

Required variables in `variables.env.local`:

```bash
# Namespace where ArgoCD is installed
ARGOCD_NAMESPACE=argocd

# Target namespace for TDP pods
TDP_NAMESPACE=tdp-testes

# Namespace where ArgoCD Applications are created (outside the argocd ns)
TDP_PROJECT_NAMESPACE=tdp-project

# Name of the "App of Apps" Application
TDP_APPLICATIONS=argo-gitops-tdp-ingestion

# URL of this git repository (used by ArgoCD to watch current/)
GIT_REPO_URL=https://github.com/your-org/tdp-gitops.git
GIT_REPO_USER=your-git-username
GIT_REPO_TOKEN_OR_PASS=your-git-token

# Helm OCI registry hosting the TDP charts
HELM_CHART_REPO_URL=registry.tecnisys.com.br/tdp/charts
HELM_CHART_VERSION=3.0.2

# Kubernetes server (use the default for in-cluster)
KUBERNETES_SERVER=https://kubernetes.default.svc

# Helm OCI registry credentials
TECNISYS_HELM_REGISTRY_USER=your-registry-user
TECNISYS_HELM_REGISTRY_TOKEN=your-registry-token
```

### 2. Configure ArgoCD to manage Applications outside the `argocd` namespace

Applications live in `TDP_PROJECT_NAMESPACE` (e.g. `tdp-project`). ArgoCD needs to be enabled to manage that namespace:

```bash
# Patch argocd-cm to enable application namespaces
kubectl patch configmap argocd-cm -n argocd --type merge \
  -p '{"data":{"application.namespaces":"tdp-project"}}'

# Restart the controllers to apply the change
kubectl rollout restart deployment argocd-server -n argocd
kubectl rollout restart statefulset argocd-application-controller -n argocd
```

> **Note**: replace `tdp-project` with the actual value of `TDP_PROJECT_NAMESPACE`.

## ArgoCD Deployment (Bootstrap — First Install)

> Run these steps only on the first install or when reconfiguring the cluster.
> Requires `helm`, `kubectl`, and `envsubst` installed.

### Step 1 — Install ArgoCD and apply common resources

The `--install` flag runs everything in sequence: registry login → installs `tdp-crds` (CRDs) → installs `tdp-argo` (ArgoCD) → waits for pods to be ready → renders templates → applies common resources.

```bash
./deploy.sh --install -v variables.env.local
```

What runs internally:
1. `helm registry login` → authenticates to the OCI registry
2. `helm upgrade --install tdp-crds` → installs ArgoCD CRDs
3. `helm upgrade --install tdp-argo` → installs ArgoCD with `application.namespaces: "*"`
4. `kubectl rollout status` → waits for `argocd-server` and `application-controller`
5. `envsubst` on all templates → populates `current/`
6. `kubectl apply` on the files in `current/common/`:
   - `argo-gitops-appproject.yaml` — TDP AppProject
   - `tdp-devops-repo-secret.yaml` — git credential for ArgoCD
   - `tdp-registry-secret.yaml` — Helm OCI registry credential
   - `argo-gitops-app-of-apps.yaml` — "App of Apps" Application

### Step 2 — Commit and push `current/` to git

The App of Apps reads `current/` **directly from the git repository**. Files need to be pushed for ArgoCD to detect them.

```bash
git add current/
git commit -m "chore: render gitops manifests"
git push origin main
```

### Step 3 — Verify the bootstrap

```bash
# Check ArgoCD pods
kubectl get pods -n argocd

# Check the App-of-Apps Application (argocd namespace)
kubectl get application -n argocd

# Initial admin password
kubectl -n argocd get secret tdp-argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d && echo
```

The App of Apps will automatically create every Application present in `current/`, with `selfHeal: true`.

## Deploying a TDP component (e.g. tdp-postgresql)

### GitOps mode (recommended)

After bootstrap, the App of Apps already watches `current/`. Just make sure the rendered file is in git:

```bash
# 1. Render (if not already done in Step 1)
./deploy.sh -v variables.env.local -p

# 2. Commit and push
git add current/tdp-postgresql/
git commit -m "feat: add tdp-postgresql application"
git push origin main

# 3. ArgoCD syncs automatically (selfHeal: true)
#    Follow the status:
kubectl get application tdp-postgresql -n tdp-project
kubectl get pods -n tdp-testes -l app.kubernetes.io/name=tdp-postgresql
```

### Direct mode (no git push)

For immediate deployment via `kubectl apply`, bypassing the App of Apps:

```bash
./deploy.sh -v variables.env.local -a tdp-postgresql
```

This renders the template and applies it directly to the cluster.

### Check status

```bash
# ArgoCD Application status
kubectl get application tdp-postgresql -n tdp-project -o wide

# Running pods
kubectl get pods -n tdp-testes

# Sync details
kubectl describe application tdp-postgresql -n tdp-project
```

## deploy.sh reference

```
./deploy.sh [OPTIONS] [COMPONENTS...]
```

| Flag | Description |
|---|---|
| `--install` | **First install**: helm login → tdp-crds → tdp-argo → wait ready → render → apply common |
| `-v FILE` | Use a custom variables file (default: `variables.env`) |
| `-p` | Only render `available/` → `current/` (no apply) |
| `-c` | Apply only common resources (`current/common/`) via kubectl |
| `-a` | Render + apply components via kubectl (does not apply common) |
| `-h` | Show help |

### Examples

```bash
# Full first-time setup (installs ArgoCD + bootstrap)
./deploy.sh --install -v variables.env.local

# Re-render templates and publish (GitOps mode)
./deploy.sh -p -v variables.env.local
git add current/ && git commit -m "chore: render" && git push

# Re-apply only common resources (AppProject, secrets, App of Apps)
./deploy.sh -c -v variables.env.local

# Direct deploy of a component (no git push)
./deploy.sh -a tdp-postgresql -v variables.env.local

# Direct deploy of multiple components
./deploy.sh -a tdp-postgresql tdp-trino -v variables.env.local
```

## Troubleshooting

### Variables not substituted in the YAMLs

Files under `common/` and `available/` are **templates** — they contain `${VAR}`. Never apply them directly with `kubectl apply`. Always use `current/` (generated by `deploy.sh -p`).

### Application stuck in `OutOfSync`

```bash
# Force sync manually
kubectl patch application tdp-postgresql -n tdp-project \
  --type merge -p '{"operation":{"sync":{"revision":"HEAD"}}}'
```

### Git or registry authentication error

Check that the secrets were applied correctly:

```bash
kubectl get secret tdp-devops-repo -n argocd -o yaml
kubectl get secret tdp-helm-oci-tdp -n argocd -o yaml
```

### Application in the wrong namespace

Applications must live in `TDP_PROJECT_NAMESPACE` (`tdp-project`), **not** in `argocd`. Confirm that `argocd-cm` has `application.namespaces: tdp-project` (see the configuration section).

### Debugging sync

```bash
# Application events
kubectl describe application <name> -n tdp-project

# Application controller logs
kubectl logs -n argocd -l app.kubernetes.io/name=argocd-application-controller --tail=100

# Force reconciliation
kubectl annotate application <name> -n tdp-project \
  argocd.argoproj.io/refresh=hard --overwrite
```

## Security

- `variables.env.local` is in `.gitignore` — never commit tokens/passwords
- Use Kubernetes Secrets for sensitive runtime data
- Rotate git and registry tokens regularly
- `TDP_PROJECT_NAMESPACE` (`tdp-project`) should have restricted RBAC
- Several `available/<component>/values.yaml` files ship with example passwords (e.g. `tdp-ranger`, `tdp-cloudbeaver`, `tdp-jupyter`, `tdp-airflow`) — these are placeholders for local/demo use only. **Change them before deploying to any real environment.**
